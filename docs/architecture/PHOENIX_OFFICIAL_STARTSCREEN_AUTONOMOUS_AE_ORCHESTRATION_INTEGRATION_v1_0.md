# PROJECT PHOENIX OFFICIAL STARTSCREEN + AUTONOMOUS A-E ORCHESTRATION INTEGRATION v1.0

Required baseline: `1700bba119cff33329fc4f2b9d71aa4369d89bf5` on `project-phoenix`.

This build integrates the proven autonomous architectural A-E delivery chain directly into `/start-v3/`.

The UI is registry-driven from `configs/phoenix/startscreen_capabilities/*.json`. Future capabilities can therefore appear without another hard-coded UI registration.

The architectural flow is:
project selection -> A-E generation -> recommended variant -> authoritative IFC -> FreeCAD -> Blender Cycles CPU -> DE TV -> project delivery manifest.

Open-source-first frontend review:
- htmx 2.x (0BSD) reviewed;
- Alpine.js 3.x (MIT) reviewed;
- neither is added because the existing local JavaScript/Fetch layer already supplies the needed browser primitives and neither replaces the Phoenix-specific orchestration, containment, persistence, registry, or governance logic.

Security:
- existing X-Phoenix-Token remains mandatory for POST;
- project JSON must resolve under `configs/projects`;
- subprocess execution uses `shell=False`;
- one architectural orchestration job at a time.

Normal outputs: `projects/runtime/<PROJECT_ID>/`.
Release remains `CONCEPT_ONLY_NOT_FOR_CONSTRUCTION`; production and for-construction stay locked.

## Installer repair R1
The installer no longer assumes or rewrites local runtime/start-screen semantic version constants.
It observes them and patches only the required structural integration anchors.

## Installer repair R2
The live start-screen integration smoke now selects a real project from the same
`status.projects` list exposed to `/start-v3/`. Only entries under `configs/projects`
are accepted. This preserves the project-containment security rule while testing
the exact UI-to-API planning path.

## Installer repair R3 — launchable architectural project catalog
The generic Phoenix `status.projects` collection can contain index or metadata JSON.
The A-E start control therefore uses a dedicated catalog generated by
`ArchitecturalOrchestrationRuntime.project_catalog()`.

Only JSON files under `configs/projects` with a real project identity are exposed.
Index files and metadata-only records are excluded. The UI reads
`status.architectural_orchestration.projects`, so an invalid generic configuration
cannot be offered as an A-E launch target.
