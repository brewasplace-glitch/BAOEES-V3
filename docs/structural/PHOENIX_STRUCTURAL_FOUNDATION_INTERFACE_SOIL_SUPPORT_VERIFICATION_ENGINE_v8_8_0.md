# Project Phoenix Structural Foundation Interface, Soil-Support & Foundation Verification Engine v8.8.0

## Purpose
v8.8.0 connects the verified structural support/joint candidate from v8.7.0 to explicit foundation and geotechnical evidence. It creates an auditable **candidate verification layer**, not a statutory geotechnical or structural approval.

## Core contracts
- Explicit foundation/geotechnical design basis with jurisdiction, standard set, edition, source and status.
- Complete support → foundation element → soil-zone interface mapping.
- Foundation reaction, soil bearing, settlement, differential settlement, uplift and sliding checks.
- Foundation beam, pile axial and pile-group capacity contracts.
- Soil spring stiffness evidence and geotechnical parameter traceability.
- Review-item generation for failed checks, missing mandatory coverage or unmapped supports.
- Central Digital Twin writeback preserving normative and geotechnical provenance.

## Safety policy
Phoenix does not invent soil properties, bearing capacities, settlement limits, pile capacities, foundation resistances, spring stiffnesses, safety factors or code limits. Those values must come from traceable project input, a verified standards/geotechnical engine or competent engineering input.

A v8.8.0 PASS means only that explicit demand/evidence is within the explicit supplied capacity/limit/evidence under the configured rules. It does **not** unlock code compliance, geotechnical approval, structural approval, foundation approval or structural model release.

## Next gate
The release remains locked pending foundation design/detail verification and competent structural/geotechnical review.
