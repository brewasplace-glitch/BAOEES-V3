# PROJECT PHOENIX 4.5 — Phase 13 bounded Level-4 batch

Phase 13 promotes Project Phoenix from an operational single-task Level-3 cycle
to one bounded Level-4 batch invocation. The committed batch contains exactly
three LOW-risk, non-executable documentation-evidence tasks with deterministic
priority and dependency order.

## Transaction boundary

All three task outputs are generated in one external candidate worktree. No
main-repository write occurs until dependency validation, multi-agent review,
accepted isolation, protected-path classification, deterministic patch replay,
the explicit 380-test regression and a verified backup all pass. Promotion is
one fast-forward merge followed by one normal non-force push.

## Bounded self-repair

One controlled trailing-whitespace defect proves the repair path. Only the
`TRAILING_WHITESPACE` failure code may be repaired, once, by deterministic
line-end trimming with before/after hashes and a new hypothesis. Security,
policy, isolation, regression, remote-race and dependency failures are never
auto-repaired.

## Safety boundaries

Automatic source, dependency, policy, registry and engine-activation changes
remain forbidden. Partial batch promotion and force push remain forbidden.
Phase-13 evidence is capability evidence and is not a professional or
for-construction release claim.
